    APPLICATION SERVER · 實作課

    AVEVA 平台實戰課程

    先學腳本何時執行、如何判斷資料，再把一筆 Modbus 模擬值送進 InTouch。腳本練習可在瀏覽器先做，實機步驟使用獨立測試 Galaxy 與模擬 PLC。

    01 掃描與觸發02 變數與控制03 PLC 到圖控

    01｜腳本什麼時候跑？

    AppEngine 的掃描像定時輪詢。先分辨物件生命週期，再選 Execute 的觸發條件。

    1. 載入Startup · 準備腳本資源
    2. 運作OnScan · 開始或恢復時初始化。Execute · 掃描時依觸發設定執行
    3. 暫停或卸載OffScan · 暫停。Shutdown · 卸載時清理資源

    在 IDE 開啟訓練物件的 Scripts 頁籤。Aliases 像路徑別名，Declarations 放要跨多次執行保留的變數，Basics 設定執行與觸發類型。可用 Attribute Browser 插入參照，先驗證語法，再存檔並檢查物件訊息。

    觸發看哪種變化
    OnTrue／OnFalse掃描看見條件轉真／轉假時觸發
    WhileTrue／WhileFalse條件持續為真／假時，按設定間隔在掃描時執行
    Periodic依設定間隔檢查執行時機
    DataChange監看的運算式資料改變時觸發

    跟做｜短暫斷線會不會被看到？

    掃描每 5 秒一次，訊號在 3 秒轉真，12 秒轉假，14 秒恢復真。按下按鈕逐次查看掃描。WhileTrue 的間隔設為 0。

    準備從 0 秒開始。

    驗收　能解釋為何 12–14 秒的短暫變化落在兩次掃描之間，15 秒不會再觸發 OnTrue。範本內用 Me 指目前實例，可避免寫死設備名稱。

    02｜變數、控制敘述與資料品質

    對照 C# 來看，腳本本體的變數像方法內的區域變數。Declarations 裡的變數可在該腳本的執行生命週期內保留值。Me 類似 this，用來參照當前物件。

    1. 用 Boolean 裝運轉狀態，Integer 裝計數，Float 裝溫度。區域變數用 loc 前綴降低與別名撞名的機會。
    2. 在測試物件先確認 SupplyTemp 與可寫入的文字欄位 TempStatus。用良好品質的模擬值驗證分支。
    3. 在 Object Viewer 對照值、品質與時間。Bad 或 Uncertain 應依專案規則處理，避免把舊值當成正常讀值。
    DIM locThreshold AS Float;
locThreshold = 30;
IF Me.SupplyTemp >= locThreshold THEN
    Me.TempStatus = "HIGH";
ELSE
    Me.TempStatus = "NORMAL";
ENDIF;

    驗收　以良好品質的 29、30、32 °C 測試，預期 NORMAL、HIGH、HIGH。此段只示範門檻分支，實作時另行驗證品質處理。

    進階練習｜迴圈、陣列與錯誤處理
    • 用 FOR 加總 1 到 5，預期 15。用 FOR EACH 逐一處理集合。簡報的 QuickScript 陣列從 1 開始。
    • WHILE 適合次數未知的工作。用小型測試資料確認條件會結束，避免拖住掃描。
    • TRY／CATCH 可記錄預期的例外。使用 .NET 物件前先確認已初始化。

    03｜從 Modbus PLC 模擬到 InTouch

    依簡報的 2023 R2 SP1 P03 訓練案例整理。此路線用 MBTCP 與 SuiteLink，可與第 4 週的 OPC UA 路線對照。

    1. 模擬器Holding Register 400001 · 原始測試值 2048
    2. 通訊與物件OI MBTCP → SuiteLink Client → Temperature001.PV
    3. 執行畫面先在 Object Viewer 驗證，再綁定 InTouch
    A｜建立單一路徑
    1. 在獨立測試環境啟動 ModRSsim2 的 Modbus TCP，依案例核對埠號 502，將 Holding Register 400001 設為 2048。
    2. 在 OCMC 的 MBTCP 訓練執行個體建立 Device Group Topic2。將 Device Item Temperature001.PV 對到測試暫存器，核對驅動的位址表示方式。
    3. 在 IDE 用 $DDESuiteLinkClient 建立訓練 Client，填入對應 Server Node、Server Name 與 SuiteLink。Topic 名稱要與 Device Group 一致。
    4. 建立 Temperature001，新增 Float 型別的 PV，以唯讀方式映射模擬點位。在 IO Devices 指派後，先部署 Client，再部署資料物件。
    5. 在 Object Viewer 觀察 PV、Quality 和更新時間。改變模擬值，確認資料跟著動。2048 是原始暫存器測試值，工程單位與縮放需另行定義。
    B｜雙 Driver 備援與斷線演練
    1. 建立第二個訓練 Driver 執行個體，核對兩端都有同名 Topic 和 Item。分別設定 Primary 與 Backup Client，先確認兩路各自能讀值。
    2. 以 RedundantDIObject 指定兩個來源，複製共同 Scan Group。依 Client → RedundantDIObject → 資料物件順序部署，將資料物件指派到備援來源。
    3. 在 Object Viewer 記錄 Active、Standby、ConnectionStatus 與 PV Quality。於隔離環境停止單一測試來源，觀察切換與恢復，再對照 Logger。
    4. 將 Reconnect 視為另一個驗證項目。依訓練腳本設定觸發及間隔，比對重試日誌與連線狀態。兩路共用同一模擬器時，練習涵蓋通訊路徑切換。
    C｜做出 InTouch 狀態畫面
    1. 在 Industrial Graphics 編輯器放入 PV 數字、P／B 狀態燈與兩路連線狀態文字。以 Active 來源驅動使用中燈號，ConnectionStatus 另外呈現。
    2. 將圖形加入訓練 InTouch 畫面並執行。先比對 Object Viewer 的 PV，再確認切換時燈號及連線文字各自更新。
    3. 記錄正常、Primary 失效、兩路皆失效與恢復情境。備援切換與重連僅操作訓練物件。

    卡住時先查　依序比對暫存器位址、Device Item、Topic、Client 連線、Object Viewer 品質及畫面參照。加密連線被拒時，保留 Logger 訊息並核對核准的安全設定。

    下載欄位對照 CSV
    如何準備並驗證 .aaPKG 範本

    目前可下載欄位表。可匯入的 .aaPKG 待從已驗證的 AVEVA 訓練 Galaxy 匯出。

    1. 在來源測試 Galaxy 確認既有的 $AHU_Training 範本與 AHU001 實例已 Check In。以 IDE 的物件匯出功能建立套件，記錄來源版本及所需相依範本。
    2. 在獨立測試 Galaxy 先建立回復點。從 IDE 的 Import → Objects → Objects from package 選取套件，先檢查重名與匯入偏好。
    3. 匯入後檢查物件、欄位與型別，重新核對目標宿主與 I/O 參照。部署後在 Object Viewer 驗證讀值，再進行第 5 週圖控練習。
