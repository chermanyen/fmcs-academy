LESSON 01

先看懂一台 AHU

AHU 是空調箱，負責處理並輸送空氣。本案例以記憶體廠的空調服務區域為背景，先學一台設備。

  1. 送風溫度：18.5°C
  2. 區域溫度：23.0°C
  3. 風機運轉與故障回授
  4. 濾網壓差：150 Pa
驗收重點
能說出 PLC 控制、AVEVA 監看各自的責任。
LESSON 02

現場到畫面的資料路徑

本例採 PLC、OI Server、SuiteLink 與 DDESuiteLinkClient 連接路徑。

  1. 感測器提供溫度與壓差訊號
  2. PLC 執行控制、連鎖與保護
  3. OI Server 依 PLC 型號使用適用驅動
  4. AppEngine 更新 AHU_001 的 Attribute
驗收重點
知道 PLC 品牌、通訊協定及驅動版本後，再設定連線。
LESSON 03

步驟 1：準備 PLC 點位表

點位表像 API 規格，先約定名稱、型別、方向與工程單位。

  1. SupplyTemp／Float／讀取／°C
  2. RoomTemp／Float／讀取／°C
  3. FanRunning、FanFault／Boolean／讀取
  4. FilterDP／Float／讀取／Pa
  5. StartRequest／Boolean／寫入
驗收重點
本頁名稱為示意別名，實際 PLC 位址須由點位表確認。
LESSON 04

步驟 2：建立執行架構

在 IDE 的 Model 配置邏輯歸屬，在 Deployment 檢查執行位置。

  1. WinPlatform：FMCS_Platform，對應執行電腦
  2. AppEngine：FMCS_Engine，承載物件
  3. Area：Cleanroom_HVAC，空調區域
  4. DDESuiteLinkClient 實例：PLC_Client
驗收重點
確認引擎指派至正確 Platform，設備歸屬正確 Area。
LESSON 05

步驟 3：建立範本與實例

從 $UserDefined 衍生 $AHU_Template，再建立 AHU_001。

  1. Templates：建立衍生範本
  2. Attributes：新增溫度、壓差與狀態
  3. 設定型別與工程單位，先用內部模擬值
  4. 儲存並 Check-in，建立設備實例
驗收重點
Object Viewer 能讀到模擬值。第二台設備可沿用同一範本。
LESSON 06

步驟 4：接上通訊與 I/O

先證明 OI Server 能讀 PLC，再設定設備 Attribute 的輸入參照。

  1. OI Server：設定裝置與通訊群組
  2. PLC_Client：設定 Server、Topic 等適用欄位
  3. AHU_001：將各屬性對應點位
  4. Validate、Check-in，部署所需物件
  5. Object Viewer：比對數值、時間與品質
驗收重點
PLC 23.0°C 與 AVEVA 相符；若為 230，確認縮放責任。
LESSON 07

步驟 5：建立操作畫面

使用已安裝且授權的 InTouch 或 OMI，綁定設備屬性。

  1. 數字元件：RoomTemp、SupplyTemp、FilterDP
  2. 風機圖示：綁定 FanRunning
  3. 故障指示：綁定 FanFault
  4. 資料品質不正常時，清楚顯示資料無效
  5. 先完成唯讀畫面，再於測試環境加入命令
驗收重點
畫面值與 Object Viewer 相符，通訊中斷不冒充正常。
LESSON 08

步驟 6：設定高溫警報

教學條件：溫度高於 25°C 持續 30 秒發報，回到 24.5°C 以下恢復。

  1. 在 RoomTemp 配置適用的高限警報
  2. 依版本設定延遲與回復死區
  3. 加入警報清單並驗證發生、確認及恢復
  4. 警報確認表示人員已知悉，不等於異常消失
驗收重點
所有門檻都是教學值，正式設定依設備及廠務規範。
LESSON 09

步驟 7：設定歷史收集

Galaxy SQL 存專案設定，Historian 保存設備時間序列。

  1. 在溫度與壓差屬性啟用 History
  2. 設定收集條件、死區與必要的強制儲存
  3. AppEngine 設定 Historian 目的地
  4. 確認服務、授權、連線，再簽入部署
  5. 趨勢查詢檢查數值、時間戳記與品質
驗收重點
Historian 歷史值主要存在 History Blocks，備份要包含它們。
LESSON 10

步驟 8：完成驗收與排錯

一次只改一個條件，沿著資料流找到問題所在。

  1. 模擬 23°C 變 26°C，確認畫面更新
  2. 持續超限 30 秒，確認發報
  3. 確認警報後，降至 24.5°C 以下檢查恢復
  4. 查趨勢確認歷史值可追溯
  5. 斷開模擬通訊，確認品質無效提示
驗收重點
先讓單路通訊穩定，再加入 RedundantDIObject 主備來源。

溫度升高後，警報會怎麼變？

高於 25°C 持續 30 秒發報，低於 24.5°C 恢復。點「推進 10 秒」加速練習，不代表現場掃描週期。
