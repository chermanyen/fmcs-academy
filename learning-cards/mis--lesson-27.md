# QuickScript .NET 與 C# 的對照

進階 / mis

## 學習目標
- 能用自己的話說明「QuickScript .NET 與 C# 的對照」的主要角色或資料關係。
- 能辨認本課常見誤解，並說明應查驗的資料或證據。

## 前置能力
先完成平台、圖控與 AHU 基礎，或回查本課前置觀念。

## 原教材重點
- 目的：設備屬性；C# 經驗：this.SupplyTemp；QuickScript .NET 觀念：Me.SupplyTemp
- 目的：條件判斷；C# 經驗：if (...) { ... }；QuickScript .NET 觀念：If ... Then ... EndIf;
- 目的：定時處理；C# 經驗：Timer／BackgroundService；QuickScript .NET 觀念：Execute 搭配 Periodic 觸發
- 目的：生命週期；C# 經驗：啟動／停止事件；QuickScript .NET 觀念：Startup／Shutdown 等類型
- 語法不同，物件責任與可維護性原則相通

## 常見問題
### 這一課應先掌握什麼？
目的：設備屬性；C# 經驗：this.SupplyTemp；QuickScript .NET 觀念：Me.SupplyTemp

### QuickScript .NET 與 C# 的觀念可如何對照？
可借用變數與條件觀念，但仍核對實際語法。概念相通不等於語法、執行環境與生命週期相同。

### 腳本中的 Me 通常用來參照什麼？
目前物件的成員。Me 的作用需放在目前物件與腳本執行環境中理解。

## 記憶卡
- 問：在掃描腳本內做長時間外部查詢，主要風險為何？
  答：阻塞掃描並影響其他工作。外部延遲會影響執行節奏，需規劃逾時與責任邊界。
- 問：衍生狀態計算前，應先檢查什麼？
  答：來源品質及輸入是否符合前提。無效輸入可能產生看似合理但錯誤的衍生結果。
- 問：腳本排錯時，哪種日誌較有幫助？
  答：含時間、物件、條件與結果的紀錄。有上下文且控制頻率的日誌，才便於還原事件。
