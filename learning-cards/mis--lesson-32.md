# 備援要分層驗證

進階 / mis

## 學習目標
- 能用自己的話說明「備援要分層驗證」的主要角色或資料關係。
- 能辨認本課常見誤解，並說明應查驗的資料或證據。

## 前置能力
先完成平台、圖控與 AHU 基礎，或回查本課前置觀念。

## 原教材重點
- AppEngine 備援處理物件執行可用性。
- PLC 備援與通訊路徑備援是另外的設計。
- SQL、Historian、電源與網路各有故障情境。
- 雙伺服器與 PLC 的可用性（概念示意）

## 常見問題
### 這一課應先掌握什麼？
AppEngine 備援處理物件執行可用性。

### 兩台 OI Server 共用一台 PLC，仍可能有什麼風險？
共用 PLC 或其他共同節點仍是單點。備援只能降低其涵蓋範圍的故障，不能消除所有共同依賴。

### 主要來源故障時，判定備用接手需要看什麼？
有效來源、值、品質、時間及切換耗時。資料仍可用才是切換成效的核心，需保留驗收證據。

## 記憶卡
- 問：主來源恢復後，可以預設一定自動回切嗎？
  答：需依實際設定與版本驗證。切換與回切策略不同，不能用教材模擬取代產品設定。
- 問：RedundantDIObject 的備援對象主要是什麼？
  答：Device Integration 資料來源。RDI 依配置協調來源，仍需驗證底層驅動與共同執行環境。
- 問：兩條路徑都失去同一台 PLC 時，應怎麼呈現？
  答：顯示資料無效並依程序處理。共同來源故障可能同時影響兩路，畫面須避免誤導。

## 課後五題測驗

1. 下列哪項符合本課的教材重點？
   A. 任何故障都可自動補救
   B. AppEngine 備援處理物件執行可用性。
   C. 只要有兩個圖示就沒有風險

2. 複習本課的操作與判讀原則，哪一項正確？

3. 主來源恢復後，可以預設一定自動回切嗎？
   A. 永遠不可能回切

4. 兩台 OI Server 共用一台 PLC，仍可能有什麼風險？
   A. 只要有兩個圖示就沒有風險
   B. 共用 PLC 或其他共同節點仍是單點
   C. 任何故障都可自動補救

5. 主要來源故障時，判定備用接手需要看什麼？
   A. 有效來源、值、品質、時間及切換耗時

## 答案與解析

2. C：本課原教材重點：PLC 備援與通訊路徑備援是另外的設計。
3. B：切換與回切策略不同，不能用教材模擬取代產品設定。
4. B：備援只能降低其涵蓋範圍的故障，不能消除所有共同依賴。
5. A：資料仍可用才是切換成效的核心，需保留驗收證據。
