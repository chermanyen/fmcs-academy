## 原教材重點
- 整合架構圖、I/O List、Tag List、採集流程、監控草圖、警報表與維運 SOP。
- 整理冷卻水、電力、空調三張畫面草圖，附警報表、趨勢規格、PLC 寫入 SQL Server 的資料流程，以及報表或 API 規格；執行正常、失聯、恢復、寫入失敗與重複資料驗收。
- 驗收需有預期結果與證據；備份、帳號權限、復原與交接文件也屬交付範圍。
- 交付三類監控草圖、警報／趨勢規格、採集入庫流程，以及一份報表或 API 規格。
- FAT／SAT 涵蓋失聯、資料庫無法寫入、重試後重複、跨日用量與表計歸零；記錄預期結果及證據。

## 常見問題
### 這一課應先掌握什麼？
整合架構圖、I/O List、Tag List、採集流程、監控草圖、警報表與維運 SOP。

### 驗收前，應先定義什麼？
情境、預期結果與通過標準。明確預期才能比較實際結果並判定差異。

### 正常、斷線與恢復情境為何都要測？
確認資料與狀態在不同條件下的行為。異常及恢復時最容易出現過期值或狀態誤判。

## 記憶卡
- 問：驗收紀錄中的時間有何用途？
  答：對照來源、切換、警報及歷史事件。共同時間軸有助於還原事件與比較耗時。
- 問：模擬驗收通過後，可以直接宣稱現場通過嗎？
  答：還需在目標環境依正式程序驗證。模擬只覆蓋它所實作的規則，不能代表實體環境全部行為。
- 問：可交接的學習成果應包含什麼？
  答：架構、點位、測試證據與待確認事項。能解釋設計與驗證依據，比單一完成標記更有交接價值。
