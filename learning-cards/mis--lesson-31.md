## 常見問題
### 這一課應先掌握什麼？
需求：即時設備狀態與圖控；建議負責位置：AVEVA 物件／圖形；原因：沿用品質、警報與模型

### C# 整合服務在本架構的責任為何？
採集、驗證、轉換及透過明確介面交換資料。服務應有清楚責任邊界，現場控制仍由對應控制層負責。

### Service 與 Repository 分工的目的為何？
分開處理流程規則與資料存取。必要的分工可降低變更影響，但不需為簡單工具增加過多層次。

## 記憶卡
- 問：外部採集失敗時，較好的重試設計為何？
  答：有逾時、間隔、上限與錯誤紀錄。受控重試能避免阻塞或對來源造成額外負荷。
- 問：唯讀 API 查詢大量歷史時，應規劃什麼？
  答：時間範圍、分頁、排序與錯誤回應。查詢契約應同時考量資料意義、效能與權限。
- 問：從瀏覽器練習通過，能否宣稱 C# 服務已上線？
  答：還需實際執行環境與整合驗證。教材模擬與真實服務是不同驗證層次。
